# SpaceLens 开发说明

## 环境和入口

Windows x64，WPF / .NET 9，SDK 9.0.319，Windows Desktop Runtime 9.0.21。
环境准备使用 `setup.ps1`，开发启动使用 `run.ps1`，回归与发布使用 `build.ps1 -Test`。
程序输出 `dist/SpaceLens/SpaceLens.exe`。
脚本兼容 Windows PowerShell 5.1，含中文的 PS1 使用 UTF-8 BOM。

公开仓库为 https://github.com/ErePasser3183/SpaceLens 。
正式安装包与便携包由 package.ps1 生成，包含更新框架及运行环境。

## 模块

`SpaceLens.Tasks` 负责进程读取、CPU 差值、程序分组及进程操作，使用现有 Core 的矩形图数据结构。
`TaskManagerView` 负责任务视图，`MainWindow.Modes` 负责切换；磁盘扫描结果与任务快照各自持有，不互相覆盖。
`MapItem` 的可选显示文本支持百分比和进程详情，磁盘模式仍默认显示文件字节大小。

CPU 用同一 PID 和进程创建时间的连续两次处理器时间差，除以采样间隔和逻辑处理器数量。
退出进程的基线会移除，PID 重用、负时间差、首次采样不会生成虚假 CPU 数值。
内存采用进程工作集，包含共享页。程序分组依据不区分大小写的进程名称，不等同于 Windows 的应用分类。
树图省略零权重和不可读项目；可读但数值为零的进程仍在列表中。

指标参考：[Microsoft 工作集说明](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.workingset64?view=net-9.0)、[进程处理器时间](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.totalprocessortime?view=net-9.0)。
结束操作先固定进程句柄并校验创建时间，再调用 [IsProcessCritical](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-isprocesscritical)；未知状态拒绝操作，不自动提权。

## 验证

- 核心检查 136 项：原磁盘检查、CPU 计算、PID 重用、聚合、筛选、真实进程采样、专门启动的测试进程的结束操作，以及内存压力判断、提前结束、失败中止、并发互斥和权限获取。
- 任务 WPF 检查 38 项：真实采样、指标切换、展开/进入、筛选、内存优化按钮状态/取消/失败、列表、布局、磁盘结果保留和最小化。
- 原磁盘矩形图交互检查 20 项。

内存优化后的任务视图最终结果和截图见 `artifacts/memory-pressure-release-tasks/`；既有磁盘回归结果见 `artifacts/header-collapse-release-interactions/`。内存优化的自动验证使用执行器替身，不实际清理整机内存；Windows 权限获取已实测。
结束进程的系统关键状态采用保守拒绝策略，未用真实系统关键进程执行破坏性测试。未测试 Standalone 发布包。

## 名称条交互

点击展开目录或程序顶部的名称条，收起该节点全部子项并恢复成完整方块；单击收起后的方块重新展开直接子项，双击仍进入。局部收起状态在数据刷新和内存/CPU切换后保留，统一层数按钮重置局部状态。

任务管理器默认一层程序方块；单击程序或使用 ＋ 展开到进程。

## 自动更新

SpaceLens.Updates 使用 Velopack 1.2.161，更新源固定为公开 GitHub Releases，仅使用正式版本，不内置任何账户凭据。应用启动关闭 Velopack 的默认启动时自动应用，统一在实际 Application.Exit 时安排静默更新，restart=false。下载未完成、取消或失败不会替换当前版本。设置关闭后不自动检查、不应用此前待更新包；用户仍可主动手动检查。

更新偏好保存于 %LOCALAPPDATA%/SpaceLens/settings.json，写入临时文件后原子替换，脱离安装内容目录。网络检查与下载异步运行；每次启动首帧显示后自动检查一次、之后每 4 小时一次，失败只更新设置菜单状态。多个请求合并，下载由 Velopack 校验散列和处理更新锁。

本地验证包含更新开关持久化、关闭/退出时取消、并发请求、待应用包、失败恢复；另有实际发布包下载、损坏散列拒绝、一次性便携副本升级和升级后 WPF 启动。不会用开发目录或用户运行目录作为升级测试夹具。

## 启动显示与磁盘删除

任务模式在首次 Show 前准备，进程采用 SoftwareOnly 绘制以规避显卡驱动合成异常。首帧检查覆盖模式、双页签、深浅主题、窗口宽度和多档栅格缩放；反馈设备的驱动白块未在开发机原样复现。

磁盘右键菜单冻结目标路径，确认后再次验证范围和创建时间。回收站操作使用 Windows Shell，无法回收时由系统请求确认；彻底删除单独确认。后台 STA 执行，结束或部分失败后更新目录；关闭实时更新时同样刷新树图、列表及汇总。检查仅真实彻底删除自建测试文件/目录，回收站使用替身验证，不操作用户数据。

下载通过 ResumableDownloader 接入 Velopack IFileDownloader，最多四个 HTTP Range 分段；包身份由 URL 和目标 SHA-256 确定，ETag/Last-Modified 校验服务器内容。缓存位于 LocalAppData/SpaceLens/downloads，各段落盘后的文件长度就是断点；退出取消请求，异常退出也可重开续传。每段最多三次尝试，30 秒无响应超时；Range 无效则退回单流。完整包合并校验后才交给 Velopack，原有旧版退出应用流程保留。跨进程文件锁防止重复实例写同一缓存。

验证包含模拟服务的分段/单流/短响应/重试/内容变化/校验失败，以及真实本机 HTTP 服务和下载子进程被终止后重新启动续传；仅终止测试自建子进程。

新包探测成功后清理其他包身份下的固定名称分段、合并临时文件和状态文件。跳过当前包、被跨进程锁占用的包、目录链接和无关文件；清理失败不阻断更新。保留零字节锁文件及目录以避免锁身份更换造成多实例竞态。回归检查覆盖旧包被替代、活动下载保护以及当前版本继续续传。
